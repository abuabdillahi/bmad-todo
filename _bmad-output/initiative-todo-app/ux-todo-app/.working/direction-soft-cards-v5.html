Soft Cards, v5

The chosen soft-cards direction, tightened. Active todos are the raised, filled cards with the strongest text; completed todos recede in both modes into hollow dashed outlines with muted text, a quiet grey check and outlined buttons, so nothing done is brighter than anything still to do. Fields grow with their text and always show an n/200 counter; cards grow too, and every vertical gap comes from one 4/8/12/16/24/32 scale.

What changed from v4: the edit cross-fade (old m5) is replaced by three alternatives to compare (m5a/m5b/m5c), and a new Button feedback section shows rest / hover / pressed / focus for every button in two press styles (P1, P2), light and dark, plus looping tap demos.

From v4: the visible loading line is gone (skeletons breathe; screen readers get a hidden status + aria-busy), and a Motion section loops each state change so you can watch it. All motion is opacity/transform/height only, 150–200 ms, and sits inside @media (prefers-reduced-motion: no-preference); with reduced motion every change is instant (see m6). Spacing, palette, counter and auto-grow are unchanged from v3.

Carried from v3: fixed the cause of the missing gaps (reset selectors like .app p / .app ul / .app button out-ranked the component classes and zeroed their margins, fonts and colours; resets now use zero-specificity :where()). Gaps on the 4/8/12/16/24/32 scale: heading→first block 16, announcer→form 16, form group→list/empty/loading 24, field→inline error 8, card→card 12, card padding 12×16, circle→text 12, text→actions 8, field/error→Save/Cancel 8. Add button top-aligned and the same height as the resting field. Focus ring offset 3px. Empty state in a quiet panel; loading skeletons use real card gap and padding. Heading is now “BMad Todos”. Palette, done treatment, counter, auto-grow, wording and announcer position unchanged.

Auto-grow uses CSS field-sizing: content; this static mock also sets each textarea's rows to its content so it reads correctly in every browser.

Motion · light phone, each frame loops one transition (watch for a few seconds)

Tokens: fast 150 ms, base 200 ms, ease-out cubic-bezier(0.2,0,0,1), ease-in-out cubic-bezier(0.4,0,0.2,1), skeleton 1.6 s, revert 1.2 s. Loops are 3 s (15 × base) or 4 s (20 × base) with a pause so each change is visible; in the app each plays once. If your OS has “reduce motion” on, frames m1–m5 sit still and only m6 changes (instantly), which is exactly what those users get.
