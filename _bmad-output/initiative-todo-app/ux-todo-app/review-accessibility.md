# Accessibility review: DESIGN.md + EXPERIENCE.md (WCAG 2.2 AA, R14)

Reviewer lens: adversarial WCAG 2.2 AA and real assistive-technology behaviour (VoiceOver macOS/iOS, NVDA, JAWS, TalkBack). The spines were not edited. Contrast ratios were recomputed from the frontmatter hex with the WCAG relative-luminance formula.

## Overall verdict

The pair has an unusually strong base. The colour system is accurate: every ratio in the DESIGN.md tables recomputes exactly. Native semantics, focus rules, the no-timer announcer and the never-disabled controls are all well judged. It is **not yet AA-safe**, though. Four spec gaps would ship real AA failures:
- the empty-submit error is never exposed to assistive technology
- delete is irreversible and unconfirmed (3.3.4)
- in dark mode, a done todo's check falls below 3:1 while the todo is being edited
- the skeleton can loop forever with no way to stop it

Several live-region and hidden-checkbox details would also likely fail the manual screen-reader pass unless the spines pin them down.

## Findings

### Critical

- **[critical]** Empty-submit error is a silent status message (WCAG 4.1.3, 3.3.1). On an empty Add/Save, focus stays in the field and "Enter a description." appears, but the only link is that it is added to `aria-describedby`. NVDA, JAWS and VoiceOver do not re-announce a description that changes on an already-focused field, so a screen-reader user who presses Enter hears nothing. A second empty submit, or Enter while over the limit (Flow 2 failure path: "Enter saves nothing"), is just as silent, because nothing in the DOM changes. AD-8 keeps field errors out of the Announcer, so the spines need a field-local mechanism, and today only the over-limit *crossing* has one (location: EXPERIENCE.md § Component Patterns — Add form, Inline error, Save button; § Interaction Primitives — Focus management "Add (invalid)", "Save or Enter (invalid)"). *Fix:* Give each field a field-local polite region that is always mounted and starts empty (reuse the over-limit region). On every blocked submit, write "Enter a description." or "Over the character limit, {n}/200", clearing it first so a repeat is announced again. Keep `aria-describedby` for when focus returns to the field. Mark the inline-error "!" icon `aria-hidden`. Add an e2e/component assertion that the region text changes on each invalid submit.

- **[critical]** Delete is neither reversible, checked nor confirmed, so it fails WCAG 3.3.4 Error Prevention (Legal, Financial, Data). The criterion is AA and covers pages that "modify or delete user-controllable data in data storage systems". A todo deleted from the server's SQLite store is exactly that, and the spine makes delete immediate "with no confirm and no undo (R5)". The ticket's Boundaries (no undo, no confirm) therefore conflict with its own R14. The risk is raised by a 40–44px Delete sitting 8px from Edit, and by the Announcer appearing above the form and shifting every card down by a banner's height during a background refetch failure. A mis-tap then destroys data permanently (location: EXPERIENCE.md § Component Patterns — Delete button; § Inspiration & Anti-patterns "Confirm dialogs and undo"; ticket Boundaries vs R14). *Fix:* This needs a product decision from the user/PO, not a UX workaround. The lightest compliant option is "Reversible": an "Undo" button in the existing "Deleted “{t}”." status announcer that re-creates the todo with its original id, text, completed flag and position. That position requires the server to accept or keep `createdAt`, so raise it with Winston (AD-6/AD-7). The alternative is to record an explicit, owned risk acceptance against R14.

- **[critical]** In dark mode, a done todo's check fails 1.4.11 while the todo is in edit mode. Edit mode forces the **active** card treatment "even for a done todo", so the checked circle (`border-done-check-dark` #666B8A, fill `surface-done-check-dark` #1C1E2B) sits on `surface-card-dark` #22253A. Edge vs card is **2.90:1** and fill vs card is 1.10:1, so the control's boundary is below 3:1. The pair is missing from the contrast table, which only checks the done check on the page (3.56) (location: DESIGN.md § Components — Todo card "Edit" state, Completion check "Checked"; § Colors — contrast table). *Fix:* Pick one: give the checked circle a dark edge of at least 3:1 on both the page and the card (e.g. `border-done-check-dark` ≈ #7A7FA0 or lighter, then re-verify against the page and its own fill), or render the check's checked style with `border-check`/`glyph-done-check` while the card is in edit mode. Then add "`border-done-check` on `surface-card` (edit mode)" to the table: light 3.61, dark must be ≥3.0.

- **[critical]** The skeleton breathes `infinite` with no pause, stop or hide (WCAG 2.2.2). The add form is usable during loading, so the "essential pre-load" exception does not apply, and the spines set no fetch timeout. A slow or hung first load leaves pulsing content running alongside interactive content for well over 5 s. That is likely on Flow 4's train and on Flow 3's cold start after a deploy. Honouring `prefers-reduced-motion` is not a pause mechanism for users who have not set it (location: DESIGN.md § Components — Skeleton card; frontmatter `motion.duration-skeleton`; EXPERIENCE.md § Motion "Loading", Rules "Nothing loops except the skeleton"). *Fix:* Cap the breathing below 5 s (e.g. `animation-iteration-count: 3` at 1.6 s = 4.8 s, then rest at opacity 1). Optionally add a first-load timeout that falls through to the List error panel.

### High

- **[high]** The Announcer's live-region mechanics are underspecified in ways that break real screen readers (4.1.3). Three gaps:
  - **Hidden region.** "Nothing is drawn and it takes no space" invites `display:none`, `hidden` or conditional mounting. A region that becomes rendered in the same tick as its text is often not announced, especially the first message, in Chrome+NVDA and Safari+VoiceOver.
  - **Atomic content.** `role="status"` is implicitly `aria-atomic="true"`. If the "!" icon and the Dismiss button sit inside the region, every message is read as "exclamation mark … Dismiss, button".
  - **Repeats.** A message identical to the current one, such as a second "Couldn't refresh the list…" or the same todo failing twice, does not change the DOM and is not re-announced.

  The over-limit region has the same repeat problem when the text crosses 200 a second time (location: EXPERIENCE.md § Component Patterns — Announcer, Character counter; DESIGN.md § Components — Announcer). *Fix:* Specify all of the following:
  - The live element is always mounted and always exposed. Collapse only the visual chrome, never with `display:none`, `visibility:hidden` or `hidden`.
  - The live element wraps **only** the message text. Icons are `aria-hidden`, and Dismiss sits outside the live element.
  - A new message clears the region and sets the text on the next frame, so repeats are spoken.
  - The over-limit region is cleared after each announcement.

  Drop the redundant `aria-live="polite"` beside `role="status"`, or keep it knowingly.

- **[high]** A visually hidden 1px native checkbox fails touch screen readers. With the usual clip-to-1px pattern, explore-by-touch on the 26px circle in VoiceOver iOS and TalkBack finds nothing focusable, because the SVG is `aria-hidden` and the label has no name. VoiceOver also draws its cursor around a 1px dot, and on some engines double-tap activation lands off-target. A manual pass on a phone (Flow 1, R8) would fail to find or toggle the check by touch (location: DESIGN.md § Components — Completion check; EXPERIENCE.md § Component Patterns — Completion check; memlog assumption). *Fix:* Keep the native input but make it `opacity:0; position:absolute; inset:0; margin:0` over the full 44×44 hit area, with `appearance:none` if needed. It then is the touch target, the explore-by-touch target and the AT focus rectangle. Keep the decorative SVG beneath it, styled through `input:checked + svg` and `input:focus-visible + svg`.

- **[high]** A successful add is silent for screen-reader users. Enter clears the field, the card appears out of view, focus stays put and nothing is announced. The user cannot tell success from a no-op or from the silent empty-submit above. Flow 2 step 2 ("The card is on top") is not something Tomás can perceive, so the manual R14 pass will flag it. Complete and edit are fine: the checkbox state and the renamed Edit button confirm them (location: EXPERIENCE.md § Voice and Tone — Overrides "Add … succeeded: No message"; § Key Flows — Flow 2). *Fix:* Announce "Added “{t}”." Two options:
  - Through the Announcer's status variant. This is visible, so it reverses the user's "delete only" decision.
  - Through the field-local hidden polite region. This needs Winston to confirm under FLAG 5 that AD-14 permits it.

  Take the choice to the user; either way, add it to Flow 2.

- **[high]** The add field's accessible name does not contain its only visible label (2.5.3; also 3.3.2). The only visible text labelling the field is the placeholder "Add a todo…", but the accessible name is the hidden label "New todo". Voice Control and Dragon users who say "click Add a todo" get no match. The placeholder also vanishes once typing starts, leaving no visible label at all (location: EXPERIENCE.md § Voice and Tone — Static strings "Text field (add)"; § Key Flows — Flow 2 step 1). *Fix:* Make the hidden label match the visible text: "Add a todo", with the placeholder "Add a todo…". Better still, consider a small persistent visible label. Update Flow 2's expected speech.

- **[high]** A failed edit throws away what the user typed, a likely 3.3.7 Redundant Entry finding. On edit failure the card reverts and the draft is discarded, and the message quotes the *pre-edit* text. Retrying means retyping the whole edit. A failed add whose field is no longer empty loses its text too, except for a 40-character truncated quote in the banner (location: EXPERIENCE.md § State Patterns — Row states "Reverted", Add form states "Add failed"; § Voice and Tone — `edit` lead). *Fix:* Keep the failed draft per todo. The next Edit on that row opens pre-filled with the failed draft, with the saved text one Cancel away. For add, keep the failed text available. One option is to offer it into the field once it is next empty. Another is to quote it in full in the announcer, since the announcer has no length limit.

### Medium

- **[medium]** The hidden Loading status will not speak on first load, and it chatters on fast loads. It is created already holding "Loading your todos" in the first React commit, and live regions that are born with content are generally not announced. Flow 3 step 2 ("Screen readers hear 'Loading your todos'") is therefore not reliable. On a fast load the text may instead be queued and spoken after the list has rendered (location: EXPERIENCE.md § Component Patterns — Loading status; § Key Flows — Flow 3). *Fix:* Mount the status empty. Set the text only if loading is still in flight after about 500 ms, and clear it on success. State this in the spine and correct Flow 3's wording.
- **[medium]** Focus hand-offs can drop to `<body>` for a frame. Delete sets the row `inert` and `aria-hidden` "at once", and m5b unmounts the focused Edit button "at once". If React applies `inert` or removes the button before the focus call runs in an effect, focus drops to `<body>` and NVDA/JAWS may announce the document or "blank" before the target (location: EXPERIENCE.md § Interaction Primitives — Focus management; § State Patterns — Leaving). *Fix:* Specify the order: move focus first, in the event handler or with `flushSync` and `useLayoutEffect`, then apply `inert`/`aria-hidden` or unmount. Add a component test asserting `document.activeElement` is never `body` across delete and edit enter/exit.
- **[medium]** Enter submits from a control that screen readers announce as "multi line". NVDA ("edit multi line"), JAWS and VoiceOver ("text area") lead users to expect Enter to add a new line. Here it submits, which may be premature, and nothing explains it. Phone keyboards show a "return" key (location: EXPERIENCE.md § Component Patterns — Text field; § Interaction Primitives — Keyboard map). *Fix:* Add `enterkeyhint="done"` to both the add and edit fields so mobile keyboards label the key as a submit. Include "Enter adds" or "Enter saves" in the field's hidden description, or accept the risk explicitly and script it into the manual pass. Do not paper over it with `aria-multiline="false"` on a `<textarea>`. Also make the IME guard tolerate Android Gboard, where every word is composing, so that Enter still submits there.
- **[medium]** VoiceOver drops list semantics from `<ul>` with `list-style: none`. Safari/WebKit removes list semantics from an unstyled list, so "Todos, list, 3 items" will not be spoken in VoiceOver on macOS or iOS (location: DESIGN.md § Components — Todo list; EXPERIENCE.md § Information Architecture row 5). *Fix:* Add an explicit `role="list"` on the Todos `<ul>`. Make the skeleton container `aria-hidden` as a whole rather than an empty `aria-busy` list. `aria-busy` is barely supported, and the Loading status already carries the state.
- **[medium]** axe-core in every e2e will be flaky over opacity animations. axe computes contrast through opacity. A scan during m5b's 120 ms fade, the Done chip fade, a card's done transition or the add enter animation can report spurious `color-contrast` violations, or "needs review" (location: EXPERIENCE.md § Motion; § Accessibility Floor — axe row; arch AD-20). *Fix:* Run e2e with `reducedMotion: 'reduce'` emulated, which the spine already makes instant, and run at least one axe scan per mode in both `colorScheme: 'light'` and `'dark'`. Otherwise, wait for `getAnimations()` to settle before each scan.
- **[medium]** The dark-mode loading cue is nearly invisible to low-vision users. Skeleton on card is 1.11:1, card on page 1.23:1 and hairline on page 1.77:1. There is no visible loading text, and under reduced motion there is no breathing either. A low-vision sighted user sees an apparently empty page, which some auditors treat as a 1.4.11 "graphical object required to understand" issue (location: DESIGN.md § Colors — decorative pairs; § Components — Skeleton card). *Fix:* Either document the skeleton as purely decorative with the hidden status as the sole carrier, an accepted risk, or raise `skeleton-dark` and the skeleton card edge toward 3:1 against the card and page.
- **[medium]** The announcer's entry shifts content under the user's finger or pointer. A background refresh failure inserts a banner above the add form and pushes every card down mid-interaction. With an irreversible delete one tap away, that invites wrong-target activation, a motor and cognitive risk (location: DESIGN.md § Components — Announcer; EXPERIENCE.md § Motion "Announcer in"). *Fix:* Resolve this together with the 3.3.4 decision: undo removes the harm. Otherwise ignore pointer activations on card buttons for about 300 ms after a layout shift, or reserve the banner's space while a refetch is in flight.
- **[medium]** The fixes above depend on FLAG 5, which is still open. The over-limit region, the Loading status and the regions proposed in the critical and high findings above all assume that AD-14's "one region" scopes to outcome messages only. If Winston rules the other way, the over-limit and empty-submit announcements lose their mechanism (location: EXPERIENCE.md § Architecture flags — FLAG 5). *Fix:* Close FLAG 5 before stories are cut, and name each field-local region in the spine (field-status region: validation only).

### Low

- **[low]** The Done chip may leak into the checkbox name. If the chip sits inside the element that the check's `aria-labelledby` points at, engines that do not prune `aria-hidden` descendants in labelledby traversal yield "Buy stamps Done" (location: DESIGN.md § Components — Done chip; EXPERIENCE.md § Voice and Tone — Completion check). *Fix:* Point `aria-labelledby` at a span that holds only the text, and render the chip as a sibling.
- **[low]** Swapping the name source in edit mode is fragile. `aria-labelledby` beats `aria-label`, so if the labelledby attribute stays while the text node is replaced, the name depends on a dangling idref (location: EXPERIENCE.md § Component Patterns — Completion check). *Fix:* In edit mode, remove `aria-labelledby` and set `aria-label`, or keep a persistent visually hidden span holding the saved text and always label by it.
- **[low]** Rows are verbose in browse mode. Each row reads the full todo text up to four times (checkbox name, visible text, "Edit “…”", "Delete “…”"), and at 200 characters that is heavy. JAWS at its default punctuation level may also voice the curly quotes (location: EXPERIENCE.md § Voice and Tone — Static strings). *Fix:* Acceptable as is, because it keeps label-in-name and makes names unique. Consider dropping the quote marks from accessible names (keep them in visible messages), and check JAWS punctuation in the manual pass.
- **[low]** NVDA and JAWS may swallow the first Escape in the edit field, using it to leave focus or forms mode before the page sees it (location: EXPERIENCE.md § Interaction Primitives — Keyboard map "Escape"). *Fix:* No spec change, since Cancel is always present. Script it into the manual pass so a "two Escapes" result is not logged as a bug.
- **[low]** Forced-colours mode (Windows High Contrast) is unspecified. The invalid edge thickens with an inset `box-shadow`, and box-shadows are removed in forced colours. SVG circle and tick colours, and any ring drawn as a shadow, may also vanish (location: DESIGN.md § Components — Text field "Invalid", Focus ring, Completion check). *Fix:* Draw rings with `outline`. Add a `@media (forced-colors: active)` rule giving the check circle `stroke: CanvasText`, the tick `CanvasText` and the invalid edge a real border. Test once in Edge.
- **[low]** Over-limit is described in words for screen readers only. Sighted users get "201/200" with a red triangle, and the phrase "over the character limit" is SR-only. That is probably sufficient for 3.3.1, but it is borderline for users with cognitive disabilities (location: DESIGN.md § Components — Character counter). *Fix:* Optionally show "201/200 · 1 over" visually. It is short and states the fix (3.3.3).
- **[low]** The `field-sizing: content` fallback contradicts "no inner scroll". Firefox, and older WebKit in the Playwright default browsers, lack `field-sizing`. A `rows` fallback scrolls internally at 320px with 200 characters (location: DESIGN.md § Components — Text field). *Fix:* Specify a small JS autosize fallback, or accept the inner scroll in those engines.
- **[low]** Type in `px` ignores the user's browser default font size. Zoom still scales it, so 1.4.4 passes, but users who raise the default font size get nothing (location: DESIGN.md § Typography). *Fix:* Consider `rem` tokens. The 1:1 token mapping makes this a one-file change.
- **[low]** Focusing the add field after Dismiss or Try again pops the phone keyboard when the user only tapped Dismiss (location: EXPERIENCE.md § Interaction Primitives — Focus management "Dismiss"). *Fix:* Keep it for keyboard activation. On pointer activation, consider moving focus to the next logical element without opening the keyboard, or accept the behaviour.
- **[low]** Done-card buttons may read as disabled. Transparent fill, grey label and grey outline are the classic disabled look, which conflicts with the spine's own "no disabled appearance" rule for some cognitive and low-vision users (location: DESIGN.md § Components — Card buttons, Done-card variant). *Fix:* Accept, as the recede is a deliberate user decision, or keep `text-done` but restore a faint fill so the buttons look pressable.
- **[low]** On a failed first load, the List error text is read twice in browse mode: once in the hidden Loading status and once in the visible panel (location: EXPERIENCE.md § Component Patterns — Loading status). *Fix:* Clear the hidden status a few seconds after it announces, or accept the duplication.
- **[low]** The delete-revert path does not say that the returning row drops `inert`/`aria-hidden`. A row that failed to delete must come back fully interactive and exposed (location: EXPERIENCE.md § State Patterns — Leaving, Reverted). *Fix:* Add one line saying the restored row is re-mounted fresh, with no `inert` or `aria-hidden`.

## Verified

- **Contrast, recomputed from hex.** Every ratio in both DESIGN.md tables matches to two decimal places, light and dark:
  - Text pairs: all ≥ 4.5. The lowest is Delete pressed in light at 4.60, then done-card pressed in dark at 4.79.
  - Placeholder and counter (`text-muted` on card): 6.72 / 6.40.
  - Over-limit counter: 6.54 / 6.60.
  - Inline error on the page: 5.85 / 8.11, and on the card in edit mode: 6.54 / 6.60.
  - Done text: 6.01 / 6.16.
  - Chip: 8.27 / 7.44.
- **Focus ring.** It clears 3:1 against every surface it sits on: page 5.55 / 10.24, card 6.20 / 8.33, announcer 5.42 / 8.84, done-check fill 4.94 / 9.15. It is the same colour as Add/Save in light (1.00:1), but the 3px offset keeps a page or card gap between them, so the adjacent colour is always page or card. Every ring fits inside the card padding, the announcer padding and the 16px page margin, so it is never clipped and nothing overlays it (2.4.7, 2.4.11).
- **Non-text contrast** (1.4.11):
  - Unchecked check: 4.64 / 4.80.
  - Hover check: 7.41 / 7.35. Pressed: 3.70 / 4.31 inside.
  - Done check on the page: 3.23 / 3.56. Its inner fill is about the page colour, at 1.12.
  - Tick: 8.27 / 7.44.
  - Field edge on the page: 3.23 / 5.90, on the card: 3.61 / 4.80.
  - Dashed done outline: 3.23 / 3.56.
  - Dismiss/Try again edges: at least 4.42 in every state.
  - Revert flag: 5.85 / 8.11.

  Soft Edit/Cancel/Delete fills (about 1.0–1.2 on the card) correctly need no boundary, because their text labels identify them.
- **Use of colour** (1.4.1). Done (fill, dashed outline, tick, chip, tone), over-limit (icon, bold, number, edge), errors (icon plus text) and revert (outline shape plus a message naming the todo) each have a non-colour cue.
- **Reflow and resize** (1.4.10, 1.4.4). At 320px the add row (about 206px field plus Add), the edit form (Save plus Cancel about 162px within about 218px) and the stacked announcer all fit. 200% and 400% zoom fall into the phone layout. Long strings use `overflow-wrap: anywhere`.
- **Text spacing** (1.4.12). Cards, fields, counter and chip all grow. The only fixed height, the 59px Add button, still fits a single "Add" line at 1.5 line-height.
- **Target size** (2.5.8). Check 44×44, card buttons 44 (phone) and 40 (wide) with min-width 64 and an 8px gap, Dismiss and Try again 44, Add 59. All are far above 24×24.
- **Names, roles and values** (4.1.2, 2.5.3). The checkbox is native, with the SVG `aria-hidden` and the state native. Edit and Delete names start with their visible label and quote the full text, so they are unique. Save, Cancel, Dismiss and Try again match their visible text. The single `<h1>`, `<main>` and the document title are correct.
- **Focus order and management** (2.4.3). DOM order matches visual order at both widths. Edit, Save, Cancel/Escape, another row's Edit, Delete (next, else previous, else the add field), not-found removal, Dismiss and Try again all have a defined target. Focus is never moved by an incoming message. A leaving row is `inert` and `aria-hidden`.
- **Timing** (2.2.1). There are no auto-dismiss timers. The 1.2s revert flag is supplementary to a message that persists.
- **Motion.** Durations are 100–200 ms. The revert flag pulses twice in 1.2s, under the 2.3.1 three-flash threshold and over a small area. Reduced motion makes everything instant, keeps colour steps and holds the flag static. 2.3.3 is AAA and is honoured anyway.
- **No hover-only content** (1.4.13): there are no tooltips or popovers, and hover only tints.
- **No disabled controls.** Validation is caught on press.
- **Errors.** `aria-invalid` and `aria-describedby` are specified on both textareas (3.3.1, 3.3.3), and the over-limit crossing is announced only on the transition, never per keystroke.
- **Announcer.** It stays visible and persistent, uses polite priority, is rendered empty on load, never takes focus, and reports outcomes without double announcement. Delete success is spoken after server confirmation, which is after the focus move. Load failure goes to the hidden status only, and refresh failure to the Announcer only.
- **3.2.6 Consistent Help** and **3.3.8 Accessible Authentication** are not applicable: there is no help mechanism and no authentication. 3.1.1 `lang="en"` is specified. There are no character-key shortcuts (2.1.4) and no dragging (2.5.7).
