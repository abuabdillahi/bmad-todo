## Intent

**Problem:** `compose.yml` has no `dev` profile, no service rotates its logs, the API's request ids are Fastify's per-process counter (`req-1` again after every restart), and nothing proves that todos survive an API restart (I6), that the API's logs are JSON with request ids and no todo text, that nginx sends its CSP, or that an invalid `PORT` stops the API.

**Approach:** Add the `dev` profile (`api-dev` extending `api` with the source mounted and `node --watch`; `web-dev` running Vite from a new `dev` Dockerfile stage, proxying `/api` unchanged to `api:3000`), `json-file` rotation on every service, UUID request ids, a config unit test and a startup exit test, and a new `profile` Vitest project that `pnpm test:all` runs against `todo-test` for I6, the log check and the header check.

## Boundaries & Constraints

**Always:** Follow AD-2 (one API replica; the `data` volume mounted only into the API service of each project), AD-4 (Vite proxies `/api` with the path unchanged; `api-dev` publishes no port and the API enables no CORS), AD-16 (dev project `todo-dev`; every variable named in `.env.example`; startup validation exits non-zero), AD-17 (`web-dev` health check is Node fetching the Vite port; `api-dev` keeps `api`'s Node `/api/health` check; `depends_on: condition: service_healthy`; `json-file` with `max-size`/`max-file` on **every** service in every profile; pino JSON with a request id), AD-19 (no todo text in logs at `info` or below; no secrets in images or compose), Conventions (`web-dev` publishes only `127.0.0.1:5173`; Vite on 5173; non-root containers). The web image's last stage stays `runtime`, so prod and test builds are unchanged.

**Never:** Changes to `ci.yml`, the deploy, `cloudflared`'s settings other than logging, nginx's headers (already present; only test them), app behaviour switched on `APP_ENV`, test-only code paths in app code, trusting a client-sent request-id header, README or `docs/quality` (story 9), the refactor sweep (story 8).

## Implementation Notes

- `vitest.config.ts`'s `profile` project sets `fileParallelism: false`, so the I6 restart never overlaps the logs or headers calls.
- `stack.ts` reads `COMPOSE_PROJECT`/`COMPOSE_PROFILE` (defaults `todo-test`/`test`), named in `.env.example` after review.
- In todo-dev, `node --watch` prints a few plain-text restart lines among the JSON logs. The logs test runs only against todo-test, which doesn't use `--watch`.
- Matrix audit: Invalid PORT → `config.test.ts` and `startup.test.ts`; Restart → I6 in `restart.profile.test.ts`; Logs → `logs.profile.test.ts`; Headers → `headers.profile.test.ts`. All ran and passed in `pnpm test:all`. Dev up and Dev reload have no repo test, because bringing up todo-dev inside `test:all` would need port 5173. ## Design Notes

- `api-dev` extends `api` so it inherits the image, health check, restart and `data` volume; compose merges `volumes` from `extends` by target path, so the bind mounts land beside `data:/data`. The alias `api` lets Vite's proxy and the prod-like name match.
- The `profile` project restarts the API, so it runs before `stop api` and after e2e, whose `beforeEach` empties the list anyway.
